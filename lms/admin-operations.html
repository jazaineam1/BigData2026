Runbook de recuperación

Restaurar sin improvisar

  1. Detener escrituras académicas. No calificar, cambiar matrículas ni ejecutar limpiezas durante la recuperación.
  2. Conservar el incidente. Registrar qué falló, hora, alcance y último snapshot conocido antes de modificar datos.
  3. Restaurar infraestructura primero. Si el problema es de proyecto completo, usar el mecanismo de restore de Supabase antes de insertar snapshots manuales.
  4. Validar identidad y cohorte. Confirmar curso, run y usuarios existentes. El snapshot académico no restaura credenciales.
  5. Restaurar por dependencias. Configuración → matrículas → sesiones/recursos → tareas → evaluaciones → entregas/notas → competencias → colaboración → eventos.
  6. Restaurar Storage por separado. Los metadatos del snapshot deben coincidir con objetos privados antes de habilitar descargas.
  7. Reejecutar QA. Validar S07, TC1, Gradebook, competencias y permisos antes de reabrir el LMS.
No hay botón “Restaurar”. Es deliberado: una restauración cambia datos académicos masivamente y debe ejecutarse con revisión, backup previo y ventana controlada.
