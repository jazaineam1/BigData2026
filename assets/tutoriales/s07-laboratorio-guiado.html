1

Analyzer → tokens → índice invertido

Primero entiende qué transforma Elasticsearch antes de hablar de score.

Concepto

El analyzer transforma texto en tokens normalizados. El índice invertido guarda término → documentos. Esa estructura evita recorrer todo el corpus en cada búsqueda.

Ejemplo

“Mantenimiento de aeronaves” puede terminar en tokens como mantenimiento y aeronave. Después el motor sabe en qué documentos aparece cada término.

Idea mínima · análisis de texto
tokens = client.indices.analyze(
    index=INDEX_NAME,
    analyzer="spanish",
    text="mantenimiento de aeronaves"
)
print([t["token"] for t in tokens["tokens"]])
¿Qué hace cada línea?
  • client.indices.analyze(...) pide al servidor ejecutar el mismo análisis que usa el índice.
  • index=INDEX_NAME hace que la prueba respete la configuración real del índice.
  • analyzer="spanish" aplica normalización lingüística adecuada para español.
  • El print no “hace búsqueda”: solo permite observar el texto ya transformado.

2

Mapping: decidir qué significa cada campo

El esquema no es decoración: determina qué se analiza, qué se filtra y qué conserva coincidencia exacta.

text

Para lenguaje natural que debe tokenizarse y participar en relevancia: descripciones, objeto contractual, nombre de entidad cuando buscas palabras.

keyword

Para valores exactos: ID de proceso, código, departamento normalizado o una etiqueta usada para filtrar/agrupar.

Mapping reducido para razonar
mappings = {
  "properties": {
    "id_proceso": {"type": "keyword"},
    "descripcion": {"type": "text", "analyzer": "spanish"},
    "departamento": {"type": "keyword"}
  }
}
¿Por qué importa?
  • Si un ID se trata como text, el analyzer puede fragmentarlo y perder la semántica de “valor exacto”.
  • Si una descripción se trata solo como keyword, buscar palabras dentro del texto deja de comportarse como búsqueda de lenguaje natural.
  • El mapping es una decisión de producto de búsqueda: debe responder a cómo consultarás después.

4

Construir la consulta por capas

No memorices JSON. Aprende qué añade cada capa y qué cambia en el ranking.

Capas

  • match: búsqueda textual básica.
  • multi_match: busca en varios campos.
  • boost: cambia importancia relativa.
  • filter: restringe sin aportar score.
  • highlight: muestra evidencia textual.

Ejemplo mental

Si “aeronaves” aparece en el nombre del proceso y en la descripción, puedes decidir que una coincidencia en el nombre pese más. Eso es una decisión explícita de ranking, no una verdad universal.

Estructura de razonamiento
query = {
  "bool": {
    "must": [{
      "multi_match": {
        "query": "mantenimiento de aeronaves",
        "fields": ["nombre^2", "descripcion"]
      }
    }],
    "filter": [{"term": {"departamento": "Bogotá D.C."}}]
  }
}
Lee el código como una frase

must: “debe responder a este texto”. multi_match: “búscalo en estos campos”. nombre^2: “una coincidencia en nombre vale relativamente más”. filter: “además restringe el universo a este departamento, pero sin premiar el score”.

5

Evaluar relevancia, no admirar scores

El score de Elastic sirve para ordenar dentro de una consulta. La calidad del buscador la evalúas contra un criterio de relevancia.

Precision@5

De los cinco primeros resultados, ¿cuántos cumplen tu criterio de relevancia? Si 4 son relevantes, Precision@5 = 4/5 = 0,8.

Experimento A/B
