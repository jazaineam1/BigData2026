Concepto clave

Partition = cajón; clustering = orden dentro del cajón

Cajón: 2026-09-03 + Bogotá
$180 MP8
$120 MP3
$40 MP5
Cajón: 2026-09-03 + Antioquia
$250 MP9
$70 MP2

Partition key: (corte, departamento) = etiqueta que localiza el cajón.

Clustering: valor_base DESC, id_proceso ASC = orden de filas dentro de ese cajón.

PRIMARY KEY ((corte, departamento), valor_base, id_proceso)
Error frecuente. En Cassandra la PRIMARY KEY no solo identifica: también determina localización y organización de los datos para la consulta.

Paso 5

Crea la tabla query-first

USE compras_claras;

CREATE TABLE IF NOT EXISTS prioridades_por_corte_departamento (
  corte date,
  departamento text,
  valor_base bigint,
  id_proceso text,
  entidad text,
  noticias_entidad int,
  nivel_menciones text,
  estado_revision text,
  url_secop text,
  criterio text,
  PRIMARY KEY ((corte, departamento), valor_base, id_proceso)
) WITH CLUSTERING ORDER BY (
  valor_base DESC,
  id_proceso ASC
);
corte + departamento

localizan la partición.

valor DESC + id ASC

ordenan de forma estable dentro de la partición.

noticias + nivel

contexto que viajó desde Atlas; no forman la PK.

Paso 7

SELECT: formula exactamente la pregunta que diseñó la tabla

SELECT id_proceso, entidad, valor_base,
       noticias_entidad, nivel_menciones, estado_revision
FROM compras_claras.prioridades_por_corte_departamento
WHERE corte='2026-09-03'
  AND departamento='Distrito Capital de Bogotá'
LIMIT 5;
Cómo se lee. Primero localiza el cajón corte + departamento. Como las filas ya están ordenadas por valor_base DESC, el LIMIT 5 obtiene las primeras prioridades de esa cola.
Control posterior. El notebook comparará los IDs y el orden con el top que pandas calculó antes. Cambiar de motor no debería cambiar la decisión de negocio.

Error plantado

La columna entidad existe, pero no localiza la partición

SELECT *
FROM compras_claras.prioridades_por_corte_departamento
WHERE entidad='MINISTERIO DEL DEPORTE';
Predice antes de ejecutar. La tabla está particionada por corte + departamento. Que entidad exista no la convierte en clave de acceso.
Si esta consulta fuera frecuente: diseñaríamos otra tabla para el patrón entidad → prioridades. ALLOW FILTERING no es un parche conceptual para un patrón de acceso que la tabla no fue diseñada para atender.

from cassandra.auth import PlainTextAuthProvider
from cassandra.cluster import Cluster

auth = PlainTextAuthProvider("token", ASTRA_TOKEN)
cluster = Cluster(
  cloud={"secure_connect_bundle": SCB},
  auth_provider=auth
)
session = cluster.connect()
OJO. "token" es el usuario literal esperado por esta ruta del driver. Cluster(...) aquí crea un objeto cliente en Python; no aprovisiona otra base en Astra.
