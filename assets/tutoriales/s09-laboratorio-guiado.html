Preparar Atlas + Colab

Preparación de acceso para practicar durante una semana. La cuenta de la consola y el usuario de Python cumplen funciones diferentes.

1 · Entrar al proyecto correcto

Inicia sesión en Atlas con tu cuenta autorizada. Comprueba organización, proyecto y clúster activo FREE. Google abre la consola; no crea el usuario con el que Python accede a la base. No crees otro clúster si el docente ya preparó uno.

2 · Crear el usuario de base de datos

Database & Network Access → Database Users → Add New Database User → Password. Elige un nombre propio. En Specific Privileges → Add Specific Privilege selecciona readWrite, Database: clase_s09_demo y Collection: secop_vectores. Activa Restrict Access y selecciona solo el clúster de práctica. Introduce y guarda una contraseña; Add User. No cambies usuarios existentes. Si el docente entrega otro ámbito, usa exactamente ese.

3 · Identificar el servidor

Cluster → Connect → Client Library/Drivers → Python. Copia solo el host situado después de @ y antes de /, terminado en .mongodb.net. En el cuaderno completa HOST_ATLAS y USUARIO_ATLAS. No copies el texto de ejemplo con <db_password> como si fuera una conexión válida.

4 · Autorizar la IP real de Colab

En la celda de conexión activa USAR_ATLAS. La salida IP_COLAB muestra la IP pública de ese runtime. Atlas → Database & Network Access → IP Access List → Add IP Address. Introduce esa IP con /32 y un comentario. Add Current IP Address corresponde al navegador, no necesariamente a Colab. No confundas ambas máquinas.

5 · Dar tiempo para practicar

En la regla IP activa Temporary IP entry y selecciona 1 week. Si existe: Edit → Modify expiration → Set expiration to 1 week from now → Confirm. Comprueba Active y el vencimiento. La semana dura siete días; no mantiene viva la máquina de Colab. Si cambia IP al reiniciar, agrega o actualiza la regla /32 y retira la obsoleta.

6 · Conectar sin escribir secretos en el código

Con la regla Active, introduce solo la contraseña en el campo oculto de Colab y pulsa Enter. quote_plus codifica símbolos automáticamente. La salida esperada es ATLAS REAL · conexión confirmada por ping a: clase_s09_demo/secop_vectores. Si hiciste la regla mientras el campo esperaba, puedes continuar ahí mismo; si falló, repite la celda. El modo URI oculta sigue disponible para quien ya tenga una URI válida.

7 · Cargar, indexar y consultar

Ejecuta las celdas siguientes en orden. Carga dos veces: el conteo del lote debe permanecer N. Crea s09_vector_index, espera queryable=True y ejecuta la consulta. Luego cambia necesidad y filtro y conserva tu expediente JSON. Un ping no prueba carga; un índice solicitado no prueba disponibilidad; una tabla NumPy no prueba Atlas.

Si falla la conexión

SalidaAcción concreta
ValueErrorRevisa host sin protocolo ni /, usuario completo, modo y campos sin completar. Una URI debe comenzar por mongodb+srv:// o mongodb://.
InvalidURI / ConfigurationErrorNo dejes marcadores de ejemplo. Usa Usuario + contraseña oculta para codificar símbolos; verifica host copiado de Connect.
ServerSelectionTimeoutErrorVerifica clúster activo, IP_COLAB /32 autorizada y Active, vencimiento, red y host. No significa por sí solo contraseña incorrecta.
OperationFailureComprueba código de error: autenticación y autorización son problemas distintos. Revisa usuario/contraseña o el alcance readWrite de la colección; no otorgues administración global para resolverlo.
Índice todavía no queryableEspera y repite la verificación. No recrees índices con otro nombre ni atribuyas el resultado local a Atlas.

Cómo se lee: cada comprobación valida una capa. Qué nos dice: si existe acceso desde Python. Qué NO permite concluir todavía: faltan carga, índice disponible y consulta. Qué error común: declarar todo listo después del ping.
