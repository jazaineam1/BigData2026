Nivel 0

¿Qué problema estamos tratando de resolver?

Una tabla puede mostrar filas de contratos. La pregunta de S06, sin embargo, requiere seguir conexiones: una entidad publica un proceso, ese proceso llega a un proveedor y ese mismo proveedor puede aparecer en procesos de otras entidades.

Entidad A → Proceso 1 → Proveedor X ← Proceso 2 ← Entidad B

SQL y pandas también pueden responder esta pregunta mediante cruces. Neo4j no es la única herramienta posible. Lo usamos porque en un grafo los nodos, relaciones y caminos son parte explícita del modelo y se pueden explorar visualmente.

Cuatro nombres que no debes confundir

Nivel 1 · construir

Tu primer grafo de juguete

Vamos a construir exactamente este ejemplo:

Alcaldía Norte ──PUBLICA──> P1 ──ADJUDICADO_A──> Tecnología Uno SAS ▲ │ Gobernación Sur ──PUBLICA──> P2 ──ADJUDICADO_A─────────┘

1. Crea tu primer nodo

CREATE (e:EntidadDemo {
  nit: "E1",
  nombre: "Alcaldía Norte"
})
RETURN e
PiezaSignificado
CREATEcrea un elemento nuevo
( ... )un nodo
evariable temporal dentro de la consulta
:EntidadDemolabel o tipo del nodo
{...}propiedades
RETURN edevuelve el nodo para verlo

Qué debes ver: en Graph, un círculo. Haz clic y confirma nit=E1 y nombre=Alcaldía Norte.

2. Crea un Proceso

CREATE (p:ProcesoDemo {
  id: "P1",
  nombre: "Compra de computadores"
})
RETURN p

3. Crea tu primera relación

MATCH (e:EntidadDemo {nit:"E1"})
MATCH (p:ProcesoDemo {id:"P1"})
CREATE (e)-[:PUBLICA]->(p)
RETURN e, p

MATCH busca elementos existentes. [:PUBLICA] es el tipo de relación. La flecha -> indica dirección.

EntidadDemo ──PUBLICA──> ProcesoDemo

4. Agrega un proveedor

CREATE (v:ProveedorDemo {
  nit: "V1",
  nombre: "Tecnología Uno SAS"
})
RETURN v
MATCH (p:ProcesoDemo {id:"P1"})
MATCH (v:ProveedorDemo {nit:"V1"})
CREATE (p)-[:ADJUDICADO_A]->(v)
RETURN p, v

Ya construiste un camino de dos relaciones: Entidad → Proceso → Proveedor.

Nivel 2 · consultar

Buscar, devolver y filtrar

5. Consulta el camino que tú mismo creaste

MATCH (e:EntidadDemo)-[:PUBLICA]->(p:ProcesoDemo)-[:ADJUDICADO_A]->(v:ProveedorDemo)
RETURN e, p, v

Qué hace: busca esa forma exacta. Qué debes ver: los tres nodos conectados.

6. Devuelve solo propiedades concretas

MATCH (e:EntidadDemo)-[:PUBLICA]->(p:ProcesoDemo)
RETURN e.nombre AS entidad,
       p.id AS proceso
LIMIT 5

AS pone un alias a la columna de salida. LIMIT acota cuántas filas se muestran.

7. Filtra con WHERE

MATCH (e:EntidadDemo)
WHERE e.nit = "E1"
RETURN e

WHERE conserva únicamente las coincidencias que cumplen una condición.

8. Añade una segunda entidad que comparta proveedor

CREATE (e2:EntidadDemo {nit:"E2", nombre:"Gobernación Sur"})
CREATE (p2:ProcesoDemo {id:"P2", nombre:"Compra de servidores"})
MATCH (v:ProveedorDemo {nit:"V1"})
CREATE (e2)-[:PUBLICA]->(p2)
CREATE (p2)-[:ADJUDICADO_A]->(v)
RETURN e2, p2, v

9. Recorre el camino entre las dos entidades

MATCH camino=(a:EntidadDemo)-[:PUBLICA]->(:ProcesoDemo)-[:ADJUDICADO_A]->(v:ProveedorDemo)
             <-[:ADJUDICADO_A]-(:ProcesoDemo)<-[:PUBLICA]-(b:EntidadDemo)
WHERE a.nit <> b.nit
RETURN camino

camino=... da nombre al recorrido completo. <> significa “distinto de”.

Qué acabas de demostrar: las dos entidades comparten un proveedor en los datos creados. No demuestra: coordinación, fraude o irregularidad.
Nivel 3 · analizar

Contar conexiones sin saltos conceptuales

10. Primero mira la variable de relación

MATCH (p:ProcesoDemo)-[r:ADJUDICADO_A]->(v:ProveedorDemo)
RETURN r

r representa cada relación ADJUDICADO_A encontrada.

11. Cuenta relaciones

MATCH (p:ProcesoDemo)-[r:ADJUDICADO_A]->(v:ProveedorDemo)
RETURN v.nombre AS proveedor,
       count(r) AS grado

Grado, en este ejercicio, es el número de relaciones directas ADJUDICADO_A que llegan al proveedor.

Tecnología Uno SAS debe tener grado 2 porque dos procesos llegan a ese nodo.

12. Ordena

MATCH (p:ProcesoDemo)-[r:ADJUDICADO_A]->(v:ProveedorDemo)
RETURN v.nombre AS proveedor,
       count(r) AS grado
ORDER BY grado DESC

DESC significa de mayor a menor.

13. ¿Qué es un hub?

Un hub o nodo concentrador es un nodo con muchas conexiones según la métrica que definiste. No es una etiqueta de riesgo.

P1 ─┐ P2 ─┼──> Proveedor X P3 ─┤ P4 ─┘

Si estamos contando ADJUDICADO_A, el proveedor parece hub porque recibe muchas relaciones.

No leas el layout como métrica. Un círculo más grande o más centrado no implica mayor grado. El conteo exacto sale de Cypher.

14. DISTINCT: grado no es lo mismo que entidades distintas

Una entidad puede tener varios procesos con el mismo proveedor. Por eso debemos diferenciar caminos de entidades únicas.

MATCH (e:EntidadDemo)-[:PUBLICA]->(:ProcesoDemo)-[:ADJUDICADO_A]->(v:ProveedorDemo)
RETURN v.nombre AS proveedor,
       count(e) AS filas,
       count(DISTINCT e) AS entidades_distintas

DISTINCT evita contar la misma entidad más de una vez.

15. WITH: pasar de una etapa a otra

MATCH (p:ProcesoDemo)-[r:ADJUDICADO_A]->(v:ProveedorDemo)
WITH v, count(r) AS grado
ORDER BY grado DESC
LIMIT 1
MATCH (p:ProcesoDemo)-[r:ADJUDICADO_A]->(v)
RETURN v, r, p, grado
MATCH → count → WITH conserva v y grado → segundo MATCH → RETURN

WITH no crea una tabla permanente. Solo pasa variables y resultados a la siguiente etapa de la misma consulta.

Nivel 4 · proteger y cargar

De un ejemplo manual a una carga reproducible

16. CREATE vs MERGE

ComandoIdea
CREATEcréalo siempre
MERGEencuéntralo por este patrón; si no existe, créalo
MERGE (e:EntidadDemo {nit:"E3"})
SET e.nombre = "Entidad de Prueba"
RETURN e

Ejecuta dos veces. El objetivo es mantener un único nodo para esa identidad.

17. Identidad: qué va en MERGE y qué va en SET

nit → identidad → MERGE nombre → atributo → SET

Usa en MERGE propiedades estables de identidad; actualiza otras propiedades con SET.

18. CONSTRAINT: impedir estados inválidos

Si el NIT identifica una Entidad, no queremos dos EntidadDemo con el mismo NIT.

CREATE CONSTRAINT demo_entidad_nit IF NOT EXISTS
FOR (e:EntidadDemo)
REQUIRE e.nit IS UNIQUE
CREATE CONSTRAINT demo_proceso_id IF NOT EXISTS
FOR (p:ProcesoDemo)
REQUIRE p.id IS UNIQUE
CREATE CONSTRAINT demo_proveedor_nit IF NOT EXISTS
FOR (v:ProveedorDemo)
REQUIRE v.nit IS UNIQUE

Comprueba:

SHOW CONSTRAINTS
Dos aclaraciones: IS UNIQUE evita valores repetidos cuando la propiedad existe; no significa automáticamente que la propiedad sea obligatoria. Y una constraint no “limpia” duplicados previos: si ya existen datos que incumplen la regla, crearla puede fallar.

19. SET: actualiza propiedades

MERGE (e:EntidadDemo {nit:"E1"})
SET e.nombre = "Alcaldía Norte Actualizada"
RETURN e

La identidad sigue siendo E1; el nombre puede cambiar.

20. UNWIND sin Python

UNWIND [
  {id:"P10", nombre:"Proceso A"},
  {id:"P11", nombre:"Proceso B"},
  {id:"P12", nombre:"Proceso C"}
] AS fila
RETURN fila.id AS id, fila.nombre AS nombre

UNWIND transforma una lista en filas individuales.

UNWIND [
  {id:"P10", nombre:"Proceso A"},
  {id:"P11", nombre:"Proceso B"},
  {id:"P12", nombre:"Proceso C"}
] AS fila
MERGE (p:ProcesoDemo {id:fila.id})
SET p.nombre = fila.nombre
RETURN p

21. Parámetros: qué significa el signo $

MATCH (e:Entidad {nit:$nit})
RETURN e

$nit es un valor recibido desde afuera. En el notebook, Python envía esos valores mediante el driver.

UNWIND $filas AS fila

La diferencia con el ejemplo anterior es solo el origen de la lista: ahora llega como parámetro.

22. Limpieza del ejemplo

MATCH (n)
WHERE n:EntidadDemo OR n:ProcesoDemo OR n:ProveedorDemo
DETACH DELETE n

DETACH DELETE elimina el nodo y las relaciones conectadas. Úsalo aquí solo para limpiar labels de demostración.

Nivel 5 · caso real

Transfiere lo aprendido a Compras Claras

El extracto real ya no usa labels EntidadDemo, ProcesoDemo y ProveedorDemo. Usa:

Entidad ──PUBLICA──> Proceso ──ADJUDICADO_A──> Proveedor

Identidad del modelo real

NodoPropiedad de identidad
Entidadnit
Procesoid
Proveedornit

Por eso la carga sigue esta secuencia:

CONSTRAINT → UNWIND → MERGE identidad → SET atributos → MERGE relación

La pregunta profesional

MATCH camino=(ancla:Entidad {nit:"TU_NIT"})-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v:Proveedor)
             <-[:ADJUDICADO_A]-(:Proceso)<-[:PUBLICA]-(otra:Entidad)
WHERE otra.nit <> ancla.nit
RETURN camino
LIMIT 30

Qué debes revisar en Graph:

  1. el nodo izquierdo es tu entidad;
  2. los dos extremos tienen NIT distintos;
  3. ambos caminos llegan al mismo proveedor;
  4. cada lado pasa por un Proceso;
  5. al hacer clic puedes inspeccionar propiedades.
Respuesta que sí está respaldada: esas entidades comparten un proveedor en los registros observados.
Respuesta que no está respaldada: que exista colusión, fraude, favorecimiento o causalidad.

Nivel 6 · profundización

H2-R: después de entender el grafo

Hasta aquí ya respondiste la pregunta de Neo4j: quién está conectado con quién y mediante qué camino. H2-R añade otra pregunta: ¿esa conectividad es alta frente a una referencia?

Para ello el notebook compara el máximo de entidades conectadas con una mediana de referencia calculada sobre las entidades candidatas con historial.

H2-R es una comparación descriptiva del extracto. No convierte conectividad en riesgo ni demuestra irregularidad.
