S06 · desde cero

Mini curso visual de Cypher

Esta guía supone que nunca has usado Neo4j. No tienes que saber Python. Aquí solo aprenderás a leer un grafo, escribir consultas básicas en Cypher y entender qué aparece en Aura Query.

Meta final: poder explicar el camino Entidad → Proceso → Proveedor ← Proceso ← otra Entidad sin mirar una solución.
0 · nombres

Neo4j, AuraDB, Cypher y Aura Query

Neo4j
Motor de base de datos de grafos.
AuraDB
Servicio en la nube donde corre Neo4j.
Cypher
Lenguaje con el que consultas Neo4j.
Aura Query
Pantalla donde escribes Cypher y ves Graph/Table/Raw.

Flujo: escribes Cypher → Aura Query lo envía a Neo4j → Neo4j responde → Graph o Table lo muestran.

1 · conexión

Primera consulta: comprobar que responde

RETURN 1 AS conexion
Qué hace
RETURN muestra un resultado. AS conexion nombra la columna.
Qué debes ver
En Table: una columna conexion con el valor 1.
2 · conceptos

¿Qué es un nodo?

Un nodo es una cosa que queremos representar. En esta sesión hay tres tipos principales:

(Entidad) (Proceso) (Proveedor)

Cada nodo puede tener propiedades. Ejemplos: una Entidad tiene nit; un Proceso tiene id y precio_base; un Proveedor tiene nit y nombre.

MATCH (e:Entidad)
RETURN e
LIMIT 5
Qué debes ver
En Graph aparecen hasta cinco nodos Entidad. No hay flechas porque todavía no pedimos relaciones.
3 · conceptos

¿Qué es una relación?

Una relación es una conexión con significado entre dos nodos.

Entidad ──PUBLICA──► Proceso
MATCH (e:Entidad)-[pub:PUBLICA]->(p:Proceso)
RETURN e, pub, p
LIMIT 5
Cómo leerlo
“Busca una Entidad que PUBLICA un Proceso.”
Qué debes ver
Pares Entidad→Proceso unidos por la flecha PUBLICA.
4 · camino

Entidad → Proceso → Proveedor

Entidad ──PUBLICA──► Proceso ──ADJUDICADO_A──► Proveedor
MATCH (e:Entidad)-[pub:PUBLICA]->(p:Proceso)-[adj:ADJUDICADO_A]->(v:Proveedor)
RETURN e, pub, p, adj, v
LIMIT 5
Qué hace
Busca el patrón completo: quién publica el proceso y a qué proveedor fue adjudicado.
Qué debes ver
Tres tipos de nodo y dos tipos de relación.

Haz clic en un nodo y mira sus propiedades. Haz clic en ADJUDICADO_A para inspeccionar la relación.

5 · vistas

Graph y Table no son dos grafos

Son dos formas de mirar el mismo resultado.

Graph
Sirve para entender quién se conecta con quién.
Table
Sirve para leer conteos y valores exactos.

Raw muestra la representación cruda. Si una consulta devuelve solo nombres y números, Table suele ser más útil. Si devuelve nodos, relaciones o un camino, Graph puede dibujarlo.

6 · medir

¿Qué es el grado?

El grado es cuántas relaciones directas tiene un nodo, según la relación que estamos contando.

Proceso 1 ─┐ Proceso 2 ─┤ Proceso 3 ─┼──► Proveedor X Proceso 4 ─┤ Proceso 5 ─┘

Aquí el proveedor tiene grado 5 respecto de ADJUDICADO_A.

MATCH (p:Proceso)-[r:ADJUDICADO_A]->(v:Proveedor)
RETURN v.nombre AS proveedor,
       count(r) AS grado
ORDER BY grado DESC
LIMIT 5
count(r) = cuenta las relaciones r.
No adivines el grado por el dibujo. La posición, tamaño o cercanía automática del círculo en Aura no equivale al grado. Table mide el número; Graph ayuda a explicarlo.
7 · interpretar

¿Qué es un hub?

Un hub, o nodo concentrador, es un nodo que reúne muchas conexiones.

Proceso ─┐ Proceso ─┤ Proceso ─┼──► PROVEEDOR HUB Proceso ─┤ Proceso ─┘

Pero “muchas conexiones” depende de qué cuentes.

Grado de adjudicaciones
¿Cuántos procesos llegan directamente al proveedor?
Entidades conectadas
¿Cuántas entidades distintas llegan a él pasando por Proceso?
Un proveedor puede tener 25 procesos de una sola entidad: grado alto, pero solo 1 entidad conectada.
8 · vista gráfica 1

Vista gráfica 1 — un proveedor con muchas conexiones

MATCH (v:Proveedor)<-[:ADJUDICADO_A]-(p:Proceso)<-[:PUBLICA]-(e:Entidad)
WITH v, count(DISTINCT e) AS entidades,
     count(DISTINCT p) AS procesos
ORDER BY entidades DESC, procesos DESC, v.nit ASC
LIMIT 1
MATCH camino=(e:Entidad)-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v)
RETURN camino
LIMIT 40
Qué debes ver: un Proveedor compartido por varias rutas Entidad→Proceso→Proveedor.
Qué mirar: haz clic en el Proveedor, después en uno de los Procesos y después en una Entidad.
Qué significa: varias entidades del extracto tienen procesos adjudicados al mismo proveedor.
Qué NO significa: no demuestra fraude, colusión ni irregularidad.
9 · islas

¿Por qué a veces veo varias islas?

Una consulta global con LIMIT puede traer coincidencias que no se conectan entre sí dentro de ese resultado. Aura las dibuja separadas.

isla 1 isla 2 Entidad→Proceso→Proveedor Entidad→Proceso→Proveedor
No son dos bases ni dos grafos diferentes. Es una sola base Neo4j y un solo resultado con grupos desconectados.
10 · vista gráfica 2

Vista gráfica 2 — dos entidades conectadas por un proveedor compartido

Entidad ancla │ PUBLICA ▼ Proceso │ ADJUDICADO_A ▼ Proveedor ▲ ADJUDICADO_A │ Proceso ▲ PUBLICA │ otra Entidad

En el cuaderno encontrarás la consulta preparada con el NIT de tu entidad. Ejecútala en Aura Query.

Qué debes ver: un camino que empieza en tu Entidad y termina en otra Entidad.
Qué comprobar: los dos NIT de Entidad son diferentes.
Qué comprobar: ambos lados pasan por el mismo Proveedor.
Qué significa: las dos entidades comparten proveedor en registros adjudicados del extracto.
Qué NO significa: no demuestra coordinación, favorecimiento, causalidad ni irregularidad.
final

Si puedes decir esto, ya entendiste el núcleo

“Neo4j representa objetos como nodos y conexiones como relaciones. Cypher usa MATCH para buscar patrones. Puedo recorrer Entidad→Proceso→Proveedor, contar relaciones para medir grado y encontrar otras entidades que comparten un proveedor.”
