1 · conceptos

Nodo, relación y camino

Entidad ──PUBLICA──> Proceso ──ADJUDICADO_A──> Proveedor

Nodo: una cosa, por ejemplo una Entidad. Relación: una flecha que une nodos. Camino: varios nodos y relaciones seguidos.

consulta 0

¿Aura responde?

RETURN 1 AS conexion

Qué hace: devuelve un valor de prueba. Qué debes ver: en Table, conexion = 1.

consulta 1

Ver Entidades

MATCH (e:Entidad)
RETURN e
LIMIT 5
MATCH busca una forma.
(e:Entidad) significa “nodo Entidad llamado e”.
RETURN e devuelve el nodo completo.
LIMIT 5 muestra hasta cinco.

En Graph: haz clic en un círculo Entidad y busca nit y nombre.

consulta 2

Una relación

MATCH (e:Entidad)-[pub:PUBLICA]->(p:Proceso)
RETURN e, pub, p
LIMIT 5
Entidad ──PUBLICA──> Proceso

Se lee literalmente: una Entidad publica un Proceso.

consulta 3

Dos relaciones

MATCH (e:Entidad)-[pub:PUBLICA]->(p:Proceso)-[adj:ADJUDICADO_A]->(v:Proveedor)
RETURN e, pub, p, adj, v
LIMIT 10
Entidad → Proceso → Proveedor

Si ves varias “islas”, no son varias bases: son componentes desconectados dentro del resultado de esa consulta.

consulta 4

¿Qué es el grado?

Proceso 1 ─┐ Proceso 2 ─┤ Proceso 3 ─┼──> Proveedor X Proceso 4 ─┤ Proceso 5 ─┘

El grado es cuántas relaciones directas estamos contando alrededor de un nodo. Aquí, grado = 5.

MATCH (p:Proceso)-[r:ADJUDICADO_A]->(v:Proveedor)
RETURN v.nombre AS proveedor, count(r) AS grado
ORDER BY grado DESC
LIMIT 10

Table mide; Graph explica. No adivines el grado por tamaño o posición del círculo.

consulta 5

¿Qué es un hub?

Un hub o nodo concentrador es un nodo con muchas conexiones según una métrica. No significa “sospechoso”.

MATCH (p:Proceso)-[r:ADJUDICADO_A]->(v:Proveedor)
WITH v, count(r) AS grado
ORDER BY grado DESC, v.nit ASC
LIMIT 1
MATCH (p:Proceso)-[r:ADJUDICADO_A]->(v)
RETURN v, r, p
LIMIT 40

Qué debes ver: un Proveedor conectado a muchos Procesos. Haz clic en el Proveedor y confirma su NIT y nombre.

diferencia clave

Grado alto no siempre significa muchas entidades

Proveedor X
5 procesos
1 entidad

grado = 5
entidades = 1
Proveedor Y
5 procesos
5 entidades

grado = 5
entidades = 5
MATCH (e:Entidad)-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v:Proveedor)
RETURN v.nombre AS proveedor,
       count(DISTINCT e) AS entidades_conectadas
ORDER BY entidades_conectadas DESC
LIMIT 10

DISTINCT evita contar varias veces la misma entidad.

consulta 6

La pregunta profesional: proveedor compartido

Entidad ancla → Proceso → Proveedor ← Proceso ← otra Entidad
MATCH camino=(ancla:Entidad {nit:"TU_NIT"})-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v:Proveedor)
             <-[:ADJUDICADO_A]-(:Proceso)<-[:PUBLICA]-(otra:Entidad)
WHERE otra.nit <> ancla.nit
RETURN camino
LIMIT 30

Qué debes revisar: los extremos tienen NIT distintos, ambos caminos pasan por Proceso y llegan al mismo Proveedor.

Sí demuestra: comparten un proveedor registrado. No demuestra: colusión, fraude, favorecimiento o causalidad.
