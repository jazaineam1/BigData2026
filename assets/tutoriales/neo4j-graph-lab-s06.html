1 · Resultado

Graph, Table y RAW cuentan la misma consulta

En AuraDB → Query, una consulta puede producir distintas vistas del mismo resultado. Para aprender grafos, usa Graph cuando devuelvas nodos, relaciones o caminos; usa Table para comprobar valores y conteos.

MATCH (e:Entidad)-[r:PUBLICA]->(p:Proceso)
RETURN e, r, p
LIMIT 10
Regla: si devuelves solo e.nombre y un conteo, no esperes un grafo navegable. Devuelve e, r, p o un camino.

2 · Tu primer camino

Entidad → Proceso → Proveedor

MATCH (e:Entidad)-[pub:PUBLICA]->(p:Proceso)-[adj:ADJUDICADO_A]->(v:Proveedor)
RETURN e, pub, p, adj, v
LIMIT 20

Qué debes localizar

Tres tipos de nodo y dos tipos de relación. La flecha no es decoración: expresa el sentido del hecho modelado.

Si puedes narrar “la Entidad publica el Proceso y el Proceso fue adjudicado al Proveedor”, ya estás leyendo Cypher como patrón.

Qué no debes hacer

No saltes visualmente de Entidad a Proveedor. El nodo Proceso conserva la unidad contractual y propiedades que usarás después.

3 · Inspección

Haz clic: el grafo tiene datos, no solo formas

Nodos

Selecciona un nodo para revisar sus propiedades. Busca:

LabelPropiedades útiles
Entidadnit, nombre, departamento
Procesoid, precio_base, modalidad, descripción
Proveedornit, nombre

Relaciones

Selecciona PUBLICA y ADJUDICADO_A. La relación también se puede inspeccionar. En esta práctica, valor_adjudicado puede estar en ADJUDICADO_A.

No mezcles: precio_base describe el proceso; valor_adjudicado describe el hecho de adjudicación reportado.
4 · Navegación

Ordena el dibujo antes de interpretarlo

Fit to screenReencuadra todos los elementos visibles.
ZoomAcerca una zona densa sin perder el resto.
ArrastrarSepara ramas y coloca el hub en el centro.

La interfaz de Query permite interactuar con el resultado gráfico. Dependiendo de la versión, puedes usar el menú contextual y expansión de vecinos para explorar más conexiones.

Advertencia esencial: el layout coloca nodos para que el dibujo sea legible. Que dos nodos se vean cerca, grandes o centrados no significa que tengan mayor riesgo, afinidad o causalidad.
5 · Grado

Un “hub” puede significar cosas diferentes

MétricaPreguntaEjemplo
grado_adjudicaciones¿Cuántos procesos distintos llegan directamente al proveedor?25 procesos
entidades_conectadas¿Cuántas entidades distintas llegan al proveedor pasando por Proceso?8 entidades
Un proveedor con 25 adjudicaciones de una sola entidad tiene grado alto, pero conectividad institucional baja. Por eso H2-R usa entidades distintas y no simplemente el grado.
WOW 1

Encuentra la estrella contractual más visible

MATCH (v:Proveedor)<-[:ADJUDICADO_A]-(p:Proceso)<-[:PUBLICA]-(e:Entidad)
WITH v, count(DISTINCT e) AS entidades,
     count(DISTINCT p) AS grado_adjudicaciones
ORDER BY entidades DESC, grado_adjudicaciones DESC, v.nit ASC
LIMIT 1
MATCH camino=(e:Entidad)-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v)
RETURN camino
LIMIT 40
Qué esperas ver: un Proveedor central y muchas ramas Entidad → Proceso → Proveedor. El efecto WOW viene de reconocer el patrón repetido, no de decorar el grafo.
WOW 1 · lectura

Desarma la estrella antes de contarla

Lectura correcta

  1. Identifica el proveedor central.
  2. Cuenta visualmente entidades distintas.
  3. Observa que cada rama pasa por un Proceso.
  4. Haz clic en una rama y revisa IDs/propiedades.
  5. Cambia a Table y valida lo que viste.

Preguntas del docente

  • ¿Cuál es el nodo puente?
  • ¿Hay varias ramas de una misma entidad?
  • ¿Qué propiedad identifica cada actor?
  • ¿Qué relación sostiene cada salto?
  • ¿Qué NO se puede afirmar con este dibujo?
Una estrella grande puede ser normal en un mercado con proveedores de alcance nacional. La conectividad es un hecho estructural; la anomalía necesita un denominador o modelo adicional.
WOW 2

Ahora parte de tu Entidad ancla

MATCH (ancla:Entidad {nit:"TU_NIT"})-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v:Proveedor)
WITH ancla, v, count(*) AS procesos_ancla
ORDER BY procesos_ancla DESC, v.nit ASC
LIMIT 1
MATCH camino=(ancla)-[:PUBLICA]->(:Proceso)-[:ADJUDICADO_A]->(v)
             <-[:ADJUDICADO_A]-(:Proceso)<-[:PUBLICA]-(otra:Entidad)
WHERE otra.nit <> ancla.nit
RETURN camino
LIMIT 30
Patrón visual: Entidad ancla → Proceso → Proveedor ← Proceso ← otra Entidad.
8 · Verificación

Cómo revisar un camino completo

1 · ExtremosConfirma que los NIT de Entidad ancla y otra Entidad sean distintos.
2 · PuenteConfirma que ambos procesos lleguen al mismo NIT de Proveedor.
3 · HechosRevisa ID de proceso, modalidad, precio base y relación de adjudicación.
Después de verificar propiedades, redacta una frase factual: “En el extracto, las entidades X e Y tienen procesos adjudicados al proveedor Z”. No agregues intención ni causalidad.
9 · Estilo útil

Haz legible el grafo, no espectacular por sí mismo

Query/Browser permite personalizar el estilo visual. Cuando esté disponible en tu interfaz, usa captions útiles: Entidad.nombre, Proceso.id, Proveedor.nombre. Puedes ajustar tamaño o apariencia para diferenciar labels.

Criterio: una personalización es buena si ayuda a responder “¿qué nodo es este?” y “¿qué relación estoy siguiendo?”. Evita tamaños que parezcan codificar riesgo si en realidad solo son estilo.

Referencia oficial: Neo4j Browser styling y result frames.

10 · Diagnóstico

Si no aparece el grafo que esperabas

ProblemaRevisa
Solo aparece TableDevuelve nodos/relaciones/caminos, no únicamente escalares.
Demasiados nodosReduce con LIMIT o empieza desde un NIT concreto.
Grafo ilegibleFit, zoom, arrastre y un límite menor.
Nodo sin nombre claroHaz clic y revisa propiedades; configura caption si está disponible.
Conteos no cuadranCambia a Table y verifica DISTINCT, NIT y patrón.
No “arregles” un resultado borrando ramas a mano. Si la consulta trae demasiado, cambia la consulta y conserva el criterio reproducible.
Cierre

Tu evidencia visual debe ser explicable

El objetivo se cumple cuando puedes mirar un grafo en Aura y explicar el camino, las propiedades y el límite de interpretación sin depender de que el profesor te diga qué estás viendo.

Puedo leerNodo, relación, dirección y camino.
Puedo verificarPropiedades y Table antes de concluir.
