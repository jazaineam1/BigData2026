S13 · 05 · CPU y ejecución

¿Cómo configurar workers en una VM de cuatro CPU lógicas?

Núcleo, CPU lógica, proceso, worker e hilo

Núcleo físico: unidad de cómputo del procesador. CPU lógica o vCPU: unidad que el sistema puede planificar; cuatro vCPU no siempre equivalen a cuatro núcleos físicos.

Worker: proceso de Dask que ejecuta tareas. Hilo: unidad de ejecución dentro de ese worker. Scheduler: asigna tareas. Partición: fragmento de datos. Nodo: máquina física o virtual; una misma VM puede contener muchos workers.

Ver configuraciones posibles: 1×4, 2×2, 4×1 y 8×1
Ejemplo con 4 vCPUConfiguración¿Qué significa?
1 worker1 proceso × 4 hilosUn proceso con cuatro hilos; depende del GIL y la tarea
2 workers2 procesos × 2 hilosDos procesos y hasta cuatro hilos
4 workers4 procesos × 1 hiloCuatro procesos independientes
8 workers8 procesos × 1 hiloPosible, pero excede las 4 vCPU: compiten por CPU y RAM

No existe un límite fijo de workers igual a núcleos. Puedes crear más workers, pero su velocidad puede empeorar. Para Python puro suele ser útil usar procesos; para NumPy, los hilos pueden aprovechar código nativo.

S13 · 06 · Almacenamiento distribuido

HDFS: entender la recuperación sin instalar Hadoop

Concepto, ejemplo y limitación

HDFS (Hadoop Distributed File System) reparte archivos en bloques y almacena copias según un factor de replicación. Si un nodo deja de estar disponible, otro puede servir los bloques que conserva.

Ejemplo manual: archivo = bloques A, B y C. Réplicas de A en nodos 1 y 2; B en 2 y 3; C en 1 y 3.

Qué NO demuestra: esta maqueta no ejecuta HDFS, no mide replicación real ni explica todos los mecanismos de coherencia.

S13 · 07 · MapReduce

Un promedio de promedios puede ser falso

Motivo, fórmula y recorrido

Map transforma cada lote en estadísticas parciales; Shuffle reúne por clave; Reduce combina sumas y cantidades. Para una media global no basta promediar las medias de cada lote: sus tamaños son distintos.

media = (Σ suma parcial) / (Σ número de casos)
def map_lote(valores):
    return sum(valores), len(valores)
parciales = [map_lote(x) for x in lotes]
media = sum(s for s,n in parciales) / sum(n for s,n in parciales)

Este cálculo es reproducible con Python. Un framework distribuido automatiza partición, envío y combinación, no corrige una fórmula equivocada.

Visualiza el tamaño de los lotes y su media

Las barras muestran registros por lote, no son barras de rendimiento. Se actualizan al calcular.

S13 · 09 · Arquitectura visual

Clúster: una máquina o varias, ¿qué cambia?

Un clúster no es necesariamente un conjunto de computadores

Un clúster de cómputo Dask está formado por un scheduler (organiza tareas), uno o más workers (las ejecutan) y recursos como CPU y RAM. Un nodo es una máquina física o virtual.

LocalClusterScheduler y workers en el mismo Codespace. Comparten CPU y memoria.
MultinodoWorkers en máquinas distintas: cada nodo aporta sus propios recursos y hay comunicación de red.
Clúster K-meansNo es infraestructura: es un grupo de puntos aprendidos por el modelo.

Identifica los recursos reales

nproc       # CPU lógicas visibles
free -h     # RAM informada por Linux
cat /sys/fs/cgroup/memory.max  # cuota si existe

La cuota de CPU y los límites del contenedor pueden ser menores que los valores del host; el cuaderno los consulta.

Alterna la arquitectura

Se verá la diferencia entre compartir memoria y sumar recursos de nodos.

En S13 ejecutamos de verdad la opción local mediante LocalCluster(...). La opción multinodo es una comparación conceptual, no infraestructura creada en Codespaces.

Conclusión comprobable

El clúster local permite aprender coordinación, pero dos workers dentro de una VM no significan el doble de RAM ni dos máquinas.

S13 · 10 · pandas frente a Dask

Misma consulta, dos motores; una referencia verificable

pandas: resultado de referencia

import pandas as pd
a = pd.read_csv('Cuadernos/datos/secop_chunks/prueba_chunk_0000000.csv')
a = a.drop_duplicates('id_del_proceso')
conteo = a.groupby('modalidad_de_contratacion').size()
print(conteo.sort_index())

groupby: agrupa filas con la misma clave. size: cuenta registros por grupo, incluyendo valores nulos según configuración del grupo. sort_index: ordena claves para compararlas.

Dask DataFrame: ejecutar tras construir el grafo

import dask.dataframe as dd
d = dd.from_pandas(a, npartitions=4)
pendiente = d.groupby('modalidad_de_contratacion').size()
conteo_dask = pendiente.compute().sort_index()
# Normaliza tipos de índice: Arrow string en Dask y object en pandas.
def como_conteos(s):
    return {str(clave): int(valor) for clave, valor in s.items()}
assert como_conteos(conteo) == como_conteos(conteo_dask)

npartitions: número de fragmentos lógicos. compute: dispara las tareas diferidas y devuelve resultado a memoria local.

Prueba crucial: el assert certifica el mismo resultado, no que Dask sea más rápido.

Interpretar

Cómo se lee: mismo conteo por modalidad. Qué nos dice: motores equivalentes para esta agregación. Qué NO permite concluir: ventaja universal de tiempo. Error: confundir API similar con ejecución idéntica.

S13 · 11 · Ejecución diferida

Dask: crear un grafo no equivale a ejecutar

La idea en tres pasos

  1. Construir: describe operaciones (read → filter → groupby → sum).
  2. Planificar: un scheduler identifica dependencias y workers libres.
  3. Materializar: compute() o persist() inicia el trabajo y espera o conserva resultados.

Persistencia: persist() busca mantener resultados distribuidos, útiles cuando se reutilizan varias veces. No debe confundirse con escribir Parquet a disco.

S13 · 12 · Tiempo y recursos

El scheduler también cuesta tiempo: ¿cuándo se recupera?

Dos mediciones diferentes

Tiempo del cálculo (clúster caliente): cuánto tardan las tareas una vez que Dask ya tiene trabajadores listos. Tiempo de primera ejecución: arranque del scheduler y los workers + envío de tareas + cómputo + reunión de resultados.

Para trabajos cortos, la apertura puede costar más que lo ahorrado. Para un servicio que procesa lotes durante todo el día, el clúster puede quedarse abierto y reutilizarse.

Aceleración total = tiempo secuencial / tiempo Dask total

Mayor que 1 significa que Dask ganó **en la medición específica**. No debemos extrapolar resultados de una VM a otra.

Cómo K-means aprovecha MapReduce

1Partir los datosCada worker recibe puntos numéricos
2AsignarBuscar el centroide más cercano
3ReducirCombinar sumas y cantidades por grupo
4Actualizar y repetirSe comparten centroides nuevos hasta converger

El código utiliza dask_ml.cluster.KMeans, no un ciclo que entrene cuatro K-means separados.

Entrenar un modelo con varias CPU puede ayudar con tareas costosas, pero no crea capacidad de cómputo nueva en la misma VM.

Conclusión comprobable

K-means es el caso práctico más sencillo para ver un solo modelo entrenado entre workers; la aceleración todavía debe medirse.

Ciclo de entrenamiento

S13 · 16 · Cuándo distribuir

CPU, RAM, disco y coordinación: cuatro cuellos de botella

Una tarea grande puede ser demandante de distintas formas

CPUMuchos puntos × variables × centroides × iteracionesEjemplo: entrenamiento repetitivo de K-means
RAMDatos, copias y estructuras superan lo disponibleEjemplo: millones de filas con muchas variables
Disco / lecturaNumerosos CSV o Parquet y transformacionesEjemplo: procesar lotes de SECOP
Espera externaMuchos servicios independientes responden lentamenteEjemplo: solicitudes de OCR (simuladas en S13)

Más workers pueden reducir espera o repartir cálculos, pero compiten por CPU/RAM en un clúster local; entre nodos aparece además el costo de red.

Dos comparaciones, dos preguntas

1. ¿Dask paraleliza? Compara tiempo secuencial con Dask de clúster caliente. Para ocho esperas independientes de 0,6 s, el mínimo ideal es ~4,8 s secuencial, ~2,4 s con 2 workers y ~1,2 s con 4, más coordinación.

2. ¿Vale la pena iniciar Dask? Compara tiempo secuencial con el total de la primera ejecución, que incluye construir el clúster. Puede perder aunque el cómputo paralelo haya ganado.

El cuestionario solo comprueba conceptos; no asigna una nota, no solicita texto libre ni reemplaza la ejecución del cuaderno.

La evidencia técnica que debe aparecer

  1. Salidas de nproc y free -h en el Codespace.
  2. Dos workers con direcciones reales en scheduler_info().
  3. Ocho tareas del mismo CSV, primero secuenciales y después Dask.
  4. resultados_identicos=True antes de hablar de velocidad.
  5. Tres tiempos: secuencial, Dask caliente y Dask con arranque.
  6. Una comparación conceptual con cuatro workers, si el entorno dispone de CPU.

Conclusión deseada: Dask tiene casos donde la concurrencia o el procesamiento de particiones ayuda; su overhead también debe considerarse. No se presupone un ganador.

Si el mismo patrón se aplica a archivos OCR, audio o Parquet, cambia el trabajo por lote, no la lógica básica del scheduler. No asumas que cuatro workers son cuatro máquinas.

S13 · 24 · Conexión con S14

Qué hace Dask y qué aprenderemos con PySpark

Aprendizajes demostrados

  1. Las CPU lógicas son capacidad disponible; los workers son procesos configurables.
  2. Un mismo Codespace puede tener 1, 2, 4 o más workers sin convertirse en varios computadores.
  3. Un scheduler Dask envía tareas a workers y puede ejecutarlas simultáneamente.
  4. MapReduce y K-means muestran cómo dividir operaciones y entrenar modelos clásicos.
  5. La demostración ejecuta lotes con Dask, comprueba resultados idénticos y mide arranque y trabajo.
  6. Las decisiones se toman sobre tiempos observados, memoria y cantidad real de tareas.
