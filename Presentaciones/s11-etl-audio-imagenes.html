¿Qué significa cada palabra? RAW es el archivo original sin cambios; fuente dice de dónde se obtuvo; crédito identifica a quién se atribuye. SHA-256 es una huella calculada desde sus bytes que permite detectar cambios, no demostrar que una noticia sea verdadera.

PNG guarda la imagen transformada; un histograma cuenta píxeles por rangos de claridad. WAV es un archivo de sonido, PCM16 representa las amplitudes con valores de 16 bits, RMS resume el nivel medio de una señal y el espectro muestra cuánto pesa cada frecuencia.

JSONL guarda una fila JSON independiente por línea; Parquet guarda una tabla binaria organizada por columnas; un manifiesto enumera archivos y huellas para comprobar la entrega. Cada original puede tener varios perfiles, o recetas de transformación.

Qué NO demuestra: 42 activos son suficientes para aprender ETL, pero no son una prueba de procesamiento distribuido a gran escala.

RAW ≠ derived

¿Por qué no sobrescribir los originales?

RAW

  • Bytes obtenidos de la fuente.
  • Crédito, colección y formato original.
  • Huellas de integridad.
  • Si el archivo ya existe con hash distinto, el proceso se detiene.

Derived

  • Nuevo formato y perfil.
  • Transformación documentada.
  • Métricas de salida.
  • Se puede reconstruir a partir de RAW y parámetros.

Ejemplo: un WEBP original no deja de ser WEBP porque guardemos un PNG gris a 320 píxeles.

Control de calidad 1

SHA-256: evidencia de integridad, no de verdad

Archivo idéntico → huella idéntica. Un solo byte alterado normalmente produce una huella completamente diferente.

sha256(raw) == original_sha256

La comprobación sucede antes de la transformación y al recuperar el expediente.

Cómo se lee: una verificación exitosa demuestra coincidencia de bytes con la huella registrada. Qué nos dice: no encontramos alteraciones. Qué NO permite concluir: que una foto sea auténtica o que el contenido de una noticia sea cierto. Error común: utilizar un hash como sustituto de una verificación de la fuente.

Extracción de audio

El archivo WAV no dice cuál es el códec

Contenedor

WAV: formato de archivo que describe una señal y su codificación.

Un WAV puede traer audio telefónico μ-law o muestras PCM.

Transformación

Decodificar WAV fuente → promediar canales → remuestrear → guardar PCM16 mono, 16.000 Hz.

Se conserva el RAW exacto y se produce un derivado separado.

Un archivo que se llama voz.wav no es automáticamente PCM16. Si lo interpretas como si lo fuera, obtendrás números inválidos o errores.

Ejemplo acústico manual

RMS: amplitud eficaz, no significado de palabras

Para muestras [0, 1, 0, -1]:

RMS = √((0² + 1² + 0² + (−1)²) / 4) ≈ 0,707

La frecuencia de muestreo es la cantidad de valores de la onda registrados cada segundo: 16.000 Hz significa 16.000 muestras/s. Los cruces por cero cuentan cuándo la onda pasa de valores positivos a negativos o viceversa.

El espectro separa un fragmento de audio por frecuencias, como descomponer un sonido en tonos graves y agudos. El centroide espectral es un promedio de esas frecuencias, ponderado por cuánto pesa cada componente. Si hay dos tonos de igual peso, 200 y 1.000 Hz, el centroide aproximado es 600 Hz. No indica qué palabras se dijeron.

Límite: RMS alto no implica enojo, calidad de servicio ni una intención específica. Necesitaríamos un modelo y referencias anotadas para analizar contenido semántico.

Qué muestra el cuaderno

La señal y su espectro cuentan cosas distintas

Onda

Amplitud en función del tiempo: cambios, silencios y saturación.

FFT / espectro

FFT es el cálculo que separa una señal en componentes de frecuencia. El espectro es el gráfico resultante: graves y agudos con distintos pesos, no palabras.

Espectrograma

Una sucesión de espectros durante la grabación: permite observar cómo cambian las frecuencias con el tiempo, pero no es una transcripción.

El cuaderno escucha una de diez voces, mide RMS/ZCR/centroide y muestra onda + espectrograma sobre el WAV derivado.

1 · Inspeccionar y preparar (11A)

Contenedor/códec: la organización del archivo y la técnica que codifica el sonido. Decodificar: recuperar muestras de la onda. PCM16: amplitudes de 16 bits. SHA-256: huella de bytes para detectar alteraciones.

Hazlo: tras el paso 5B, ejecuta 11A y mira la duración, los canales, el códec real y la huella. Salida: AUDIO INSPECCIONADO.

2 · Voz a texto (11B)

ASR: reconocimiento automático de voz; es el proceso que intenta producir palabras a partir de una señal. Segmento: fragmento con tiempos de inicio y fin. Un modelo preentrenado necesita descargarse para hacer inferencia.

Hazlo: activa ACTIVAR_ASR para obtener una transcripción real sin servicios de pago. Si falta modelo o conexión, el ejercicio continúa usando un texto de práctica marcado como tal. No confundir RMS con ASR.

3 · Encontrar datos en el texto (11C)

Entidad: nombre de institución o persona, como la SIC. Cantidad: una magnitud como «más de cincuenta compañías», que no significa 50 exactas. Regex: patrón de caracteres para buscar menciones. Evidencia: palabras originales que respaldan un candidato.

Hazlo: revisa las tablas de entidades, números y temas. Busca una frase del audio que puedas escuchar para comprobar el resultado. Salida: EVIDENCIAS VERIFICADAS.

4 · Entregar sin inventar relaciones (11D)

Ficha: JSON con procedencia, códec, SHA, candidatos y fragmentos textuales de respaldo. La noticia y foto están vinculadas por article_id; un audio no se asocia solo porque el archivo tiene un número parecido. Las voces de MINDS-14 son de servicios financieros y no pertenecen a las noticias de El Tiempo.

Hazlo: ejecuta 11D y reabre la ficha. Salida: EXPEDIENTE MULTIMODAL CREADO.

Mini reto: selecciona una institución, una cantidad y un tema del audio. Verifica cada mención en el texto y, cuando haya voz disponible, escúchala. Distingue texto ASR real, transcripción aportada y paráfrasis de práctica. Las cifras y entidades son candidatos, no hechos ni contratos certificados.
