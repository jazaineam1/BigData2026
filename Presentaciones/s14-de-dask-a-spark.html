Arquitectura

Driver, executors, particiones y tareas

Mapa conceptual

Driver — coordina el plan↓
Executor A · TaskExecutor B · Task
↓Resultado y controles

Un executor es un proceso; una partición es una porción lógica; una task realiza una unidad de trabajo sobre una partición.

Del trabajo al motor

  • Driver: construye y coordina la aplicación.
  • Job: trabajo activado por una acción.
  • Stage: tareas que comparten una fase de ejecución.
  • Shuffle: movimiento de datos entre particiones.
Importante: Spark en Colab con local[2] corre en un computador. Dos tareas no equivalen a dos servidores.

¿Qué significa aumentar particiones?

Herramienta · 24 filas lógicas

Simulación visual del reparto; el reparto real se comprueba en el cuaderno con spark_partition_id().

¿Qué podemos concluir?

  • Más particiones pueden crear más oportunidades de paralelismo, con coste de coordinación.
  • Una partición no representa un equipo físico.
  • La distribución puede ser desigual o cambiar por el optimizador.
  • Para mover filas entre particiones se puede requerir shuffle.
En la celda 8 del cuaderno ejecutarás un repartition real sin usar una API RDD.

Dos fórmulas, dos interpretaciones

Media de razones = ((a/A) + (b/B)) / 2
Cobertura conjunta = (a + b) / (A + B)

DataFrame

Crear el indicador anual sin promediar porcentajes

Agregación en PySpark

resumen = (
    df.withColumn("anio", F.substring("mes",1,4))
      .groupBy("anio")
      .agg(F.sum("emparejados").alias("n"),
           F.sum("procesos_unicos").alias("d"))
      .withColumn("cobertura", F.col("n")/F.col("d"))
)
resumen.show()

Funciones clave

FunciónNecesidad
withColumnDerivar el año.
groupByReunir filas por clave.
aggSumar numerador y denominador.
showEjecutar y leer algunas filas.
2026 contiene un periodo parcial del snapshot; no lo compares con un año completo como si fueran equivalentes.
